# Landing Page Overrides

These rules override the DBTLint master system for the public landing page.

## Pattern

Use an evidence-first operations narrative:

1. Fixed navigation with one primary CTA
2. Split hero: outcome-led copy plus a live lint-run artifact
3. Capability bento grid
4. Three-stage workflow rendered like a CI pipeline
5. Three-tier pricing with Team as the recommended operational default
6. Final CTA followed by compact product navigation

## Page-specific rules

- Keep the page dark regardless of the application theme so the product console and status colors stay coherent.
- Lead with the quality-gate outcome; describe features as proof, not as a checklist.
- Use a single green CTA path: registration. Secondary actions are neutral.
- Show believable product-state examples, but do not present demo metrics as customer claims.
- Keep below-fold sections full-width with a centered 1200px content frame.
- On mobile, collapse every split layout into one column and retain the product preview directly after hero copy.
